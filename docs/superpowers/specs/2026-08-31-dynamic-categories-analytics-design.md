# Dynamic Document Categories and Analytics Design

## Goal

Ship the third LafLabs administration increment:

1. replace hard-coded document categories with an Admin-managed taxonomy;
2. make Admin and public document filtering immediate, compact, and URL-addressable;
3. add useful time-series charts to Admin Analytics without turning it into a generic SaaS dashboard;
4. expose one consent-aware, type-safe Analytics hook for future public interactions.

This increment must remain independently deployable. Site-wide search, embeddings, public AI answers, image hosting, and internal mail systems remain separate projects.

## Confirmed Direction

- Use the existing PostgreSQL, Next.js App Router, Admin authorization, audit log, locale system, and consented first-party Analytics pipeline.
- Add Recharts for accessible responsive charts; do not introduce an external CMS or Analytics provider.
- Keep the LafLabs Admin surface in Operate mode: square controls, flat bands, precise rules, restrained Route Blue, familiar form behavior, and no decorative motion.
- Keep document category slugs stable. Admins may change Korean and English labels, ordering, and active state, but may not rename a slug after creation.
- Do not permanently delete categories. Deactivation preserves existing documents, URLs, audit history, and referential integrity.
- Do not collect search terms, document titles, email addresses, URLs, or other free-form values in Analytics events.
- Do not collect Admin usage in the public traffic Analytics dataset.

## Scope

### Included

- A versioned `document_categories` data model, migration, repository, service, protected Admin API, and Admin management page.
- Seed data for every existing canonical category.
- Category-backed document validation and editor options.
- Immediate Admin document filters with debounced URL search and no Apply button.
- Dynamic public document category filters, page-local title/summary search, and latest/oldest sorting.
- Daily Analytics series for visitors, page views, and public interaction events for 7, 30, and 90 days.
- LafLabs-styled Recharts visualizations with accessible text/table equivalents.
- A public-only `useAnalytics()` hook and bounded document interaction events.
- Korean and English copy, loading/empty/error states, responsive layouts, keyboard access, and reduced-motion behavior.

### Excluded

- Site-wide navigation search, command palette, semantic search, embeddings, vector storage, or AI-generated answers.
- Changes to AI summary generation, Agent settings, or OpenAI credentials.
- Image server, asset library, mailing server, newsletter delivery, or internal operations tools.
- Category nesting, arbitrary color assignment, icons, per-category permissions, or localized slugs.
- Permanent category deletion.
- Admin behavior tracking in the public Analytics event store.
- Previous-period comparisons, forecasts, cohorts, funnels beyond the existing product-to-contact funnel, or export files.

## Architecture

The increment is one pull request containing two vertical slices that share no persistence tables:

1. **Document taxonomy and discovery** owns category data, document validation, Admin management, public filters, sorting, and page-local search.
2. **Analytics insight and instrumentation** owns daily aggregation, charts, and the public consent-aware tracking hook.

The slices use the existing Admin shell and design vocabulary but remain independently testable and commit-ready. A failure in Analytics must not prevent document authoring, and a category-management failure must not affect the Analytics dashboard.

## Document Category Model

Add a `document_categories` table with:

| Column | Type | Rule |
| --- | --- | --- |
| `id` | UUID | Primary key, generated by PostgreSQL |
| `kind` | `document_kind` | `notice`, `legal`, or `disclosure` |
| `slug` | text | Lowercase kebab case, 1–64 characters, immutable |
| `label_ko` | text | Trimmed, 1–80 visible characters |
| `label_en` | text | Trimmed, 1–80 visible characters |
| `sort_order` | integer | Non-negative; ties resolve by creation time and ID |
| `active` | boolean | Controls new selection and filter visibility |
| `version` | integer | Starts at 1 and increments on every mutation |
| `created_by` | text | Admin GitHub identifier |
| `updated_by` | text | Admin GitHub identifier |
| `created_at` | timestamptz | PostgreSQL timestamp |
| `updated_at` | timestamptz | PostgreSQL timestamp |

Constraints and indexes:

- unique `(kind, slug)`;
- check the slug against `^[a-z0-9]+(?:-[a-z0-9]+)*$`;
- check `sort_order >= 0`;
- index `(kind, active, sort_order, created_at, id)`;
- add a composite foreign key from `document_series(kind, category)` to `document_categories(kind, slug)` after seed rows exist. PostgreSQL skips the foreign-key check when nullable `category` is null.

The migration seeds these existing values with their current Korean and English labels:

- notice: `general`, `service`, `maintenance`, `security`;
- legal: `privacy`, `terms`, `cookies`, `policy`;
- disclosure: `corporate`, `financial`, `governance`, `material`.

Existing document rows remain unchanged. The migration inserts taxonomy rows before adding the foreign key, so every current non-null category resolves.

## Category Domain Rules

- A category slug is chosen at creation and never edited.
- Labels, order, and active state are editable through optimistic version matching.
- Deactivating a category does not change existing document series.
- An inactive category remains readable in existing document details and direct filtered URLs, but it is hidden from new-document selection and the default public filter toolbar.
- A draft that already references a newly inactive category may still be saved without changing its category. Once changed away, the inactive category cannot be selected again.
- Category creation, label update, activation, deactivation, and reorder operations write bounded metadata to `admin_audit_log`.
- Reordering receives the complete ordered ID list for one document kind. The service verifies membership and updates all positions atomically.
- Concurrent label/state changes return `409 version_conflict`; stale reorder membership returns `409 category_set_changed`.

## Category Interfaces

Create focused taxonomy modules rather than adding more responsibility to document validation and storage:

- `lib/document-categories/types.ts` — domain DTOs and repository contracts;
- `lib/document-categories/validation.ts` — slug, label, mutation, and reorder schemas;
- `lib/document-categories/store.ts` — PostgreSQL reads and atomic mutations;
- `lib/document-categories/service.ts` — domain rules, version conflicts, and audit-safe errors;
- `lib/document-categories/cache.ts` — cached public active-category reads;
- `lib/document-categories/admin.ts` — mapping for Admin presentation where needed.

Protected endpoints:

- `GET /api/admin/document-categories?kind=<kind>&includeInactive=true`;
- `POST /api/admin/document-categories`;
- `PATCH /api/admin/document-categories/[categoryId]`;
- `POST /api/admin/document-categories/reorder`.

All mutations require Admin authorization, same-origin validation, bounded JSON, strict schemas, and stable machine-readable errors. API responses never expose audit internals.

Public content pages read categories on the server through the cached category service. The public content API validates a supplied category against the taxonomy before reading documents. An unknown category returns `400 invalid_category`; an existing inactive category remains valid for historical links.

## Admin Category Experience

Add `/admin/documents/categories` and link it from the Documents workspace. The page is task-oriented rather than dashboard-like:

- one document-kind switcher;
- one ordered table/list with slug, Korean label, English label, status, and row actions;
- inline label editing;
- explicit Activate/Deactivate actions;
- keyboard-accessible Move up/Move down ordering controls rather than drag-only behavior;
- a compact Add category form that asks for slug and both labels;
- localized confirmation for deactivation when published or editable documents reference the category;
- informative empty, loading, conflict, and unavailable states.

Route Blue marks the current document kind and primary action only. Status is expressed through text, border, and tone; no pills, rounded cards, colored category chips, or ornamental charts are introduced.

## Document Authoring Integration

Remove `categoriesByKind` as the runtime source of truth. Static types may retain `DocumentKind`, but valid categories come from the category service.

Server pages load active categories before rendering the editor. `DocumentEditor` receives category DTOs as props and displays localized labels. Existing drafts also receive their selected inactive category so the current value remains legible and saveable.

Document services validate `(kind, category)` against the category repository before create, update, schedule, or publish. Database referential integrity remains the final guard. Publication snapshot checks continue comparing the canonical slug, not the localized label.

## Admin Document Filter Experience

Remove the Apply filters link. The filter state remains encoded in the URL so links, pagination, refresh, back, and forward navigation remain reliable.

- Kind, status, and locale selects call `router.replace()` immediately.
- Search updates after a 300 ms debounce and trims whitespace before writing the URL.
- Any filter change removes the cursor and returns to the first page.
- The current query renders immediately as pending UI while server results refresh; controls remain usable.
- Clear filters is one explicit square control shown only when a filter is active.
- Pagination uses the last applied URL state.
- The interface announces result updates and exposes native labels and focus states.

Client-side filtering of the already loaded page is removed. The server result is the only displayed result, preventing a partial page from appearing to represent the full dataset.

## Public Document Discovery

The shared document index supports three URL parameters:

- `category=<slug>`;
- `sort=latest|oldest`, default `latest`;
- `q=<trimmed query>`, limited to 100 visible characters.

Search matches published title and summary with escaped case-insensitive PostgreSQL matching. It does not search full Markdown bodies; full-site and semantic search belong to PR 4.

The toolbar uses square controls in this order: category filter, sort, search, clear. On desktop it is one compact row; on narrow screens search takes its own full-width row while filter and sort remain side by side. Category and sort controls use native `select` elements so keyboard, screen-reader, and mobile picker behavior remain predictable.

The page keeps server rendering, cursor pagination, canonical locale switching, and cache tags. Category and sort-only result sets remain cacheable. Requests containing `q` bypass the shared list cache so arbitrary visitor terms never become persistent cache keys. Category mutations invalidate category and relevant document-index tags.

## Analytics Data Model and Query

No new Analytics event table is required. Extend `AnalyticsSummary` with a zero-filled daily series for the selected range:

```ts
type AnalyticsDailyPoint = {
  date: string
  visitors: number
  pageViews: number
  productClicks: number
  githubClicks: number
  contactClicks: number
  contentFilters: number
  contentSorts: number
  contentSearches: number
}
```

The store groups consented events by UTC calendar date across the existing 7-, 30-, or 90-day range. Missing dates are filled in application code so charts never shift or omit the baseline. Distinct visitor counts are computed per day; they are not summed to claim a unique visitor total across the full range.

Existing totals, funnel, locale/device distribution, referrers, product targets, and GitHub targets remain intact.

## Analytics Dashboard Experience

Add Recharts and render two primary visual sections:

1. **Traffic over time** — visitors and page views in a restrained two-series line/area chart.
2. **Interaction over time** — product, GitHub, contact, filter, sort, and search events in a stacked bar chart, with low-volume series still inspectable through the legend and tooltip.

Design rules:

- use Route Blue for the primary series and existing blue-grey/navy tokens for supporting series;
- keep square chart containers, flat borders, and no shadows or gradient decoration;
- use compact fixed-size Admin typography rather than homepage display scales;
- show exact values through tooltips and a screen-reader-accessible daily data table;
- never communicate a series through color alone;
- disable chart entrance animation under reduced motion and keep ordinary transitions within 150–250 ms;
- show a skeleton-shaped chart region during navigation and a teaching empty state when no events exist;
- preserve 390 px, 768 px, and 1440 px layouts without horizontal page overflow.

The range selector remains URL-based. Changing range requests a new server summary and charts use the same snapshot as totals and tables.

## Consent-Aware Analytics API

Keep `createAnalyticsClient()` as the transport and add a small React-facing interface:

```ts
type PublicAnalytics = {
  track(type: AnalyticsEventType, targetId: AnalyticsTargetId | null): void
}

function useAnalytics(): PublicAnalytics
```

The hook reads the existing consent provider and returns a stable no-op tracker unless Analytics consent is active. It never creates a second visitor/session identity and never bypasses Do Not Track.

Add three public event types:

- `content_filter` with a bounded target such as `notice:category:service`;
- `content_sort` with a bounded target such as `notice:sort:oldest`;
- `content_search` with a bounded target such as `notice:search`.

The target schema accepts only canonical document kinds, operations, category slugs, and sort values. The raw search query is never passed to `track()`, queued, sent, stored, or logged. Admin routes do not mount or call these interactions.

Future public components use `useAnalytics().track(...)`; no wrapper component or render-prop abstraction is added until repeated markup proves it useful.

## Error Handling

- Taxonomy APIs return stable localized-at-UI codes: `invalid_category`, `slug_conflict`, `version_conflict`, `category_set_changed`, and `unavailable`.
- Public pages ignore malformed query parameters and render the canonical unfiltered state; public APIs reject them with `400`.
- If a category is deactivated between editor load and save, the service permits the unchanged current category but rejects a newly selected inactive category with `409 category_inactive`.
- Analytics aggregation failures use the existing protected Admin error boundary and do not affect public event collection.
- Recharts is presentation-only. Chart rendering failure must not remove the totals and tabular data already returned by the server.
- Tracking failures remain silent to visitors and never interrupt filtering, sorting, search, navigation, or consent withdrawal.

## Security and Privacy

- All category mutations require GitHub organization Admin authorization and same-origin requests.
- Every body and query is bounded and strictly validated.
- Slugs are data, never SQL identifiers; all values remain parameterized.
- Category labels are rendered as text, not HTML.
- Audit metadata contains IDs, kinds, slugs, changed field names, and state transitions only.
- Analytics retains its signed pseudonymous identity, retention jobs, rate limits, consent requirement, withdrawal deletion, and DNT behavior.
- Search terms and authored content never enter Analytics target IDs.
- Admin navigation and category management do not contribute to public visitor metrics.

## Accessibility and Localization

- Every new Admin and public string is added to both Korean and English catalogs with key-parity tests.
- Labels, category names, dates, numbers, empty states, errors, and confirmations follow the selected locale.
- Slugs, IDs, and event target identifiers remain canonical and untranslated.
- Tables retain semantic headers; charts include text summaries and accessible tabular equivalents.
- Reordering works with keyboard controls and announces the new position.
- Filters use native labels, focus visibility, and result-count announcements.
- Reduced motion removes chart animation and nonessential transitions.

## Testing

### Taxonomy

- Migration integration test seeds all current categories, preserves document references, and verifies the composite foreign key.
- Repository tests cover ordered reads, inactive reads, unique slugs, optimistic updates, reorder atomicity, and audit rows.
- Service/API tests cover authorization, same-origin, body limits, validation, conflicts, inactive behavior, and safe errors.
- Component tests cover creation, bilingual label editing, activation, deactivation, reordering, focus, and conflicts.

### Documents and filters

- Document workflow tests prove new/changed category validation comes from the repository.
- Existing inactive category drafts remain saveable; new inactive selections fail.
- Admin filter tests verify immediate URL replacement, debounce, cursor reset, clear, and server-only results.
- Public API/page tests verify dynamic categories, search escaping, latest/oldest cursors, invalid queries, cache keys, pagination, and locale preservation.

### Analytics

- Store tests cover UTC buckets, zero-filled days, distinct daily visitors, each event series, and 7/30/90-day boundaries.
- Dashboard tests cover charts, accessible tables, empty data, locale formatting, and reduced motion.
- Client/hook tests prove consent and DNT gating, stable no-op behavior, bounded targets, silent failure, and absence of raw queries.

### Full regression

- TypeScript, ESLint, all Vitest tests, and the production build.
- Browser tests at 390 px, 768 px, and 1440 px for Admin categories, Admin documents, Admin Analytics, and public notices.
- One bounded visual inspection round across desktop and mobile, one batch fix, and at most one confirmation round.
- Impeccable detector over only the changed Admin/public UI targets after implementation is complete.

## Deployment and Rollback

The normal Vercel build applies migrations before compiling the application. The migration is additive: create and seed `document_categories`, add indexes/constraints, then add the composite foreign key. It does not rewrite document slugs or delete content.

Rollback of application code is safe only if the older application continues writing one of the seeded categories. The new table and foreign key may remain during rollback. New categories created after deployment would be rejected by an older hard-coded application, so rollback operations should deactivate those categories and avoid editing affected documents until the new application is restored.

Recharts adds client code only to the protected Analytics route. Public document pages do not load Recharts.

## Success Criteria

- An Admin can create, relabel, reorder, activate, and deactivate document categories without a deployment.
- Existing documents preserve their category and remain readable when a category is inactive.
- New documents can select only active categories for their kind.
- Admin document filters update without an Apply button and never display client-filtered partial results.
- Public document indexes support dynamic categories, latest/oldest order, and page-local title/summary search with stable URLs.
- Admin Analytics shows accurate zero-filled daily traffic and interaction series for 7, 30, and 90 days while preserving existing totals and funnel data.
- New public document interactions are tracked through one consent-aware hook without storing raw search terms or affecting Admin traffic.
- Korean and English, keyboard access, reduced motion, mobile layouts, privacy withdrawal, and existing document/AI workflows remain intact.
